# Intelligent Network Intrusion Detection Agent — FoAI Case Study

## What's in this folder

```
IDS_Agent_Project/
├── README.md                  ← you are here
├── design_document.md         ← PEAS, architecture, decision rules, analysis (submit this)
├── prompts_used.md            ← AI-assistance disclosure (submit this)
├── python/
│   ├── agent.py                 ← the agent: sense() / decide() / act()
│   └── analysis.py              ← runs the small-scale analysis, produces CSV + chart
├── analysis_output/            ← results.csv + decisions_chart.png (generated by analysis.py)
└── web-ui/
    └── index.html               ← standalone showcase UI — no install needed
```

No external dataset and no ML library is used anywhere in this project —
every decision is made by hand-specified rules over connection statistics.

## For the showcase / demo (easiest option)

Double-click `web-ui/index.html` — it opens in any browser, no server, no
install. Drag the sliders to adjust a connection's stats (duration, bytes
sent, failed logins, hosts contacted, connection rate, destination port),
or click one of the sample chips (*normal browsing / brute-force login /
port scan / data exfiltration / DoS flood*). The page updates live, showing
which rule fired, why, and what action the agent takes.

This is the best thing to have open on your laptop screen when presenting
to your mentor — let them drag the sliders themselves.

## For the code submission

```bash
cd python
python agent.py          # single-record demo, prints Sense/Decide/Act output
python analysis.py       # runs all 5 sample traffic profiles, checks against expected labels
```

`analysis.py` needs `matplotlib` for the chart (optional):
```bash
pip install matplotlib
```
If it's not installed, the script still runs and just skips the chart.

## For the viva

Read `design_document.md` first — PEAS breakdown, architecture diagram, and
a table explaining exactly why each rule exists. Be ready to explain:
- Why a rule-based agent is a legitimate "AI strategy" (classical
  expert-systems paradigm)
- What real attack behavior each rule (R1–R4) approximates
- The honest limitation of hand-picked thresholds (section 5 of the design
  doc) and how they could be replaced with values learned from real traffic
  data
